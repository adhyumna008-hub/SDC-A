PART 2: SYSTEM ARCHITECTURE & TECH STACK
--------------------------------------------------------------------------------

Client Application Layer:
- Framework: React 18 with TypeScript
- Build Tool: Vite
- Styling: Tailwind CSS (responsive from mobile 320px to 4K displays)
- Iconography: Material Symbols Outlined / Lucide Icons
- Barcode / QR Scanning: html5-qrcode
- Animations: Pure CSS hardware-accelerated transforms and canvas

Backend & Infrastructure (Google Cloud Firebase):
- Firebase Authentication: Google OAuth popup + Email/Password authentication.
- Cloud Firestore: Real-time NoSQL document database with onSnapshot listeners.
- Firebase Hosting: Global CDN Edge deployment with single-page app rewrite rules.
- Dual-Layer Cache: Combines Firestore snapshots with browser local storage for
  instant, zero-latency state rendering.

Role-Based Access Control (RBAC):
- "admin": Whitelisted email accounts (adhyumna008@gmail.com, studentdevelopersclub88@gmail.com).
  Full management access: scanner, reports, publishing, moderation, history.
- "member": Users authenticating with the host college institutional domain (@vardhaman.org).
  Access to internal events, idea hub submission, team registration, certificates.
- "guest": External users (Gmail or other college domains).
  Access to open radar, inter-college hackathons, external college input.

--------------------------------------------------------------------------------
PART 6: DATA INTEGRITY & BUSINESS RULES
--------------------------------------------------------------------------------
1. Payload Sanitization:
   Cloud Firestore strictly rejects any document containing "undefined" values.
   All payloads must pass through cleanObjectForFirestore() before addDoc or
   updateDoc calls. Solo events must strip teamCode/teamName if undefined.

2. Single-Scan Check-in Rule:
   QR passes can only be scanned once for attendance. If checkedIn === true,
   subsequent scans must be blocked with an explicit duplicate warning showing
   the previous check-in timestamp.

3. Institutional Segregation:
   Users must specify whether they belong to the host institution or an external
   university. Reports must subdivide presentees and absentees accordingly.

4. Moderation Clearance:
   When an idea proposal is approved or rejected by an admin, it must be purged
   from the pending moderation panel and excluded from the public Idea Hub feed.
